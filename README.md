# Azure Cloud Services — Coursework

Hands-on Microsoft Azure coursework covering infrastructure automation, web app deployment, disaster recovery, and identity/access management.

## 📖 What's in here

### Infrastructure Automation (Azure CLI)
A Bash script (`Create_environment_for_LB-Test.sh`) that provisions a complete load-balancing test environment from scratch using the Azure CLI:
- Creates a resource group and virtual network
- Creates an **availability set** and provisions 3 VMs into it
- Opens port 80 on each VM and uses the **Custom Script Extension** to automatically install IIS and configure a unique per-VM landing page — a working example of automated, repeatable infrastructure provisioning rather than manual console clicking

### PowerShell Administration Scripts
- **SMB protocol configuration** — detecting and toggling SMBv1/SMBv2/SMBv3 support on an SMB server (SMBv1 disabling is a standard security hardening step)
- **Azure Files SMB mount script** — testing connectivity to an Azure Storage Account file share over port 445 and persistently mounting it as a network drive

### Web App Deployment
Deployed a web app to **Azure App Service** without using GitHub or Azure's built-in publish feature: built the site in Visual Studio Code, then deployed it via **FileZilla** (FTP) directly into the app's `wwwroot` directory using deployment credentials generated in the Azure Portal.

### Disaster Recovery & Backup Concepts
A written deep-dive covering:
- **RTO (Recovery Time Objective)** and **RPO (Recovery Point Objective)** — what they mean and the factors (bandwidth, storage, replication) that affect meeting them
- **Retention policies** — short-term vs. long-term vs. infinite retention, and the cost trade-offs involved
- **Network Watcher** — using **IP Flow Verify** to check NSG allow/deny decisions, and **Connection Troubleshoot** to test TCP/ICMP connectivity between VMs
- **Crash-consistent vs. Application-consistent backups** — speed, recovery process, and data-consistency trade-offs
- **Web App Service (PaaS) vs. IIS on a VM (IaaS)** — a full comparison across software installation, security, backup, deployment, and scaling responsibilities

### Identity & Access Management
Configured a **Conditional Access policy** in Microsoft Entra ID to enforce **Multi-Factor Authentication (MFA)** for admin accounts, scoped to specific network locations (Sweden and Norway IP ranges) — including creating the target admin user accounts and assigning them roles.

### Remote Access
RDP connection profiles used to manage the provisioned Azure VMs directly (sensitive connection details redacted for this repo).

## 🧰 Tools & concepts used
Azure CLI, Azure Virtual Network, Availability Sets, Custom Script Extension, Azure App Service, Azure Storage (Files/SMB), PowerShell, FileZilla, Network Watcher (IP Flow Verify, Connection Troubleshoot), Azure Backup (RTO/RPO/Retention), Microsoft Entra ID, Conditional Access, MFA

## 🔒 Note on redacted content
One script originally included a live Azure Storage Account access key (auto-generated by Azure's own "Connect" feature) and two RDP files included real VM public IPs. These have been redacted before publishing, since they could point to real (if likely inactive) cloud resources.

## 💡 What I learned
Practical experience across the full Azure lifecycle: automating infrastructure provisioning via CLI rather than manual clicks, deploying applications through multiple methods, understanding the real trade-offs behind backup and disaster recovery planning, diagnosing network connectivity with Azure's built-in tools, and configuring conditional, location-aware identity security policies.
